# Builds (GitHub Actions)

`.github/workflows/build.yml` builds the installation app on Windows, Linux and macOS and the presets zip,
without a local machine of each OS.

## When it runs

- **Manually**: Actions > *Build apps* > *Run workflow* (pick the branch you want to build).
- **On a tag** `v*`: the four jobs run and then publish a GitHub release with every asset.

## The payload is not in git

`app/payload/` is ignored on purpose (see [AUDIT.md](AUDIT.md)): it holds the compiled module, the button
textures and the romfs files generated from the game dump. The workflow downloads it from a release asset
instead of building it (that would need the dump and LLVM on the runner).

One-time setup, repeated only when the payload changes:

```bash
python tools/make_release.py       # stage app/payload (needs the dump, LLVM and the tools)
python tools/make_payload_zip.py   # writes release/payload.zip
```

Upload `release/payload.zip` to a release with the tag **`payload`** (GitHub > Releases > Draft a new release,
tag `payload`, attach the file). With the GitHub CLI:

```bash
gh release create payload release/payload.zip -t "Build payload" -n "app/payload for the CI builds"
# or, if the release already exists:
gh release upload payload release/payload.zip --clobber
```

`tools/ci_payload.py` downloads that asset into `app/payload` at the start of every job and fails with a
clear message if the release or the file is missing.

## Assets produced

| Job | File | Release asset |
|---|---|---|
| Windows | `release/SHB-OcarinaTweaks.exe` | `SHB-OcarinaTweaks.exe` |
| Linux | `release/SHB-OcarinaTweaks-linux` | `SHB-OcarinaTweaks-linux` |
| macOS | `release/SHB-OcarinaTweaks-macos.dmg` | `SHB-OcarinaTweaks-macos.dmg` |
| Presets | `release/SuperHeroBoost-<version>-presets.zip` (+ `.sha256`) | same name |

Every asset carries its platform in the name: `.exe` is Windows, `-linux` is the Linux binary (ELF, no
extension by convention) and `-macos.dmg` is the macOS disk image with the `.app` inside. The names match what
`app/updater.py` looks for (it also still accepts the older names), so the in-app update check keeps working.

The release job then replaces the auto-generated notes with `docs/RELEASE-<version>.md` when that file exists,
so the release page shows the full notes instead of just the changelog link.

## Notes

- Linux builds on **ubuntu-22.04** on purpose: an older glibc means the binary runs on newer distros
  (Arch/CachyOS, Fedora, Ubuntu 24.04+). Do not move it to a newer runner unless you accept a narrower range.
- macOS builds on `macos-latest` (Apple Silicon). If you also need Intel Macs, add a `macos-13` job and build
  with `--target-arch universal2`, or publish a separate asset.
- macOS binaries are not signed or notarized: users may need to right-click > Open the first time, or
  `xattr -dr com.apple.quarantine /Applications/SHB-OcarinaTweaks.app` after copying it from the dmg.
- Linux users need `chmod +x SHB-OcarinaTweaks-linux` after downloading if the browser drops the permission.
- The presets zip is generated by `tools/build_app.py` in every app job too; the workflow publishes the copy
  from the `presets` job only, so there is a single artifact.
- PyInstaller cannot cross-compile, which is why there are three jobs instead of one.
